## Hardcoding and maintainability findings

The maintained React/TypeScript path already follows lazy route boundaries,
typed API services, TanStack Query for server state, and colocated page modules.
The audit removed retired route code that still contained fixed environment
domains, a `123/123` demo login, and bearer-token query URLs. Public service
configuration now flows through `src/config/env.ts`, and all upstream targets
remain outside the bundle.

Legacy JS/JSX and `@ts-nocheck` files are now exact allowlists. The list may
shrink through migration; CI rejects any expansion.

## Backend/database conclusion

The frontend contract is synchronized with the reviewed production OpenAPI at
the time of this audit. The database itself cannot be declared synchronized.
There is no application-managed migration ledger, the deployed production JAR
does not embed a Git SHA, and the backend repositories are divergent. This is a
release-governance blocker, not a frontend schema task.

Required backend closure:

1. Merge the organization and integration backend changes into one canonical
   reviewed commit.
2. Introduce an ordered, checksummed migration tool and baseline the current
   schema without rerunning historical one-shot SQL.
3. Embed backend Git SHA and migration version in a non-secret health endpoint.
4. Deploy the same backend release to Dev and Prod, then verify OpenAPI and
   migration versions before promoting this frontend artifact.
